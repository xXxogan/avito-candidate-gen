# Avito Candidate Generation — решение для этапа кандидатогенерации

**Recall@50 на валидации: 0.4742** (baseline BM25: 0.3534)  
Готовый файл сабмита: `outputs/answer.csv` — 2452 запроса × 50 item_id, проходит валидацию формата.

## Подход

### Multi-source retrieval

Три независимых источника кандидатов, дающих разное покрытие:

1. **BM25 по полному тексту** (title + description + infm_params, лемматизированные) — основной источник, 344K уникальных объявлений.
2. **BM25 только по заголовкам** (`item_title_lemma`) — ловит короткие точные совпадения, которых полнотекстовый BM25 «тонет» в длинных описаниях.
3. **Char n-gram (TF-IDF + cosine, n=2..4) по заголовкам** — ловит опечатки («электирик» -> «электрик») и слова вне словаря лемматизатора. Работает без лемматизации.

Union трёх источников (до ~600 кандидатов на запрос) покрывает **63.6% релевантных** против 54.8% у одиночного BM25 top-200.

### Подготовка запросов

- Лемматизация через `pymorphy3` для BM25-источников.
- Нормализация (lowercase, схлопывание пробелов/пунктуации).
- Декодировка раскладки (`fix_keyboard_layout`): запросы, набранные в английской раскладке (`'ktrnhbrf ghjdjlrf` → `электрика проводка`), исправляются автоматически. Применяется только если все декодированные слова найдены в словаре pymorphy — это отсекает ложные срабатывания на артикулах и английских словах.

### Линейный реранк

Скор кандидата = взвешенная сумма признаков:

| Признак                                   | Вес  | Обоснование                                                                                                                                             |
| ----------------------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bm25_norm`                               | 1.0  | Основной лексический сигнал                                                                                                                             |
| `char_sim`                                | 0.3  | Единственный новый источник с ненулевым весом (опечатки/раскладка)                                                                                      |
| `loc_match`                               | 0.5  | **Главный буст**: 83% релевантных пар совпадают по `location_id`. Вес 0.5 — компромисс: жёсткий фильтр (1.0+) теряет 17% релевантных из других локаций. |
| `params_overlap`                          | 0.75 | Пересечение токенов `search_infm_params_text` с `item_infm_params_text` (overlap 0.97 на релевантных).                                                  |
| `title_coverage`                          | 0.25 | Доля токенов запроса в заголовке — запросы короткие и стилистически близки к заголовкам.                                                                |
| `bm25_title_norm`                         | 0.0  | Как вес вредит (дублирует лексический сигнал), но как _поставщик кандидатов_ в union полезен.                                                           |
| `pop_norm`, `rating_norm`, `reviews_norm` | 0.0  | В линейной формуле не работают (pop вредит — вытесняет точные совпадения). Оставлены для обучаемого реранкера.                                          |

Сортировка устойчивая (`mergesort`): при равенстве скора сохраняется порядок первого источника (BM25).

### Добивка

Если у запроса меньше 50 кандидатов после реранка (на практике не случается при top_k=200), строка добивается популярными объявлениями корпуса (по кликам в train + числу отзывов) — страховка от коротких строк в сабмите.

## Результаты экспериментов

| Этап | Подход                                             | Recall@50  |
| ---- | -------------------------------------------------- | ---------- |
| 1    | BM25 baseline (full text)                          | 0.3534     |
| 2    | + Linear rerank (loc/params/title) на BM25 top-200 | 0.4658     |
| 3    | + Multi-source (title BM25 + char n-gram) + rerank | **0.4742** |

Потолок union-пула (recall@200): 0.6364. Линейная формула извлекает 74% доступного пула. Остальное — нелинейные взаимодействия, например, «популярность важна только при совпадении локации». Они возможно решаемы обучаемым реранкером, который не был включен в решение.

## Запуск

Требуется Python 3.14

```bash
# Клонирование и вход в проект
cd avito-candidate-gen

# Установка зависимостей (uv быстрее и воспроизводимее)
uv sync
# или: pip install -e .

# Генерация answer.csv
uv run python scripts/make_submission.py
```

**Первый запуск** — до 10-15 минут (лемматизация корпуса 189K объявлений, построение трёх индексов).  
**Повторный запуск** — 1-3 минуты (всё кэшируется в `data/processed/`).

Результат: `outputs/answer.csv` — CSV с колонками `query_id`, `answer` (item_id через пробел), UTF-8, без индекса.

## Валидация формата (встроена в make_submission.py)

Проверяются все требования ТЗ:

- ровно 2 колонки: `query_id`, `answer`
- строка на каждый `query_id` из `benchmark_queries.parquet` (2452 строки, без дублей и пропусков)
- 1–50 `item_id` в строке, без повторов внутри строки
- каждый `item_id` — 16 символов `0-9a-f`, существует в `benchmark_items.parquet`
- порядок строк — как в `benchmark_queries`

При любом нарушении — `AssertionError` с описанием проблемы.

## Используемые библиотеки

- `bm25s` — быстрый BM25 на C++/Rust
- `scikit-learn` — `TfidfVectorizer` для char n-gram
- `pymorphy3` — лемматизация русского языка
- `pandas`, `numpy` — работа с данными
- `pyarrow` — чтение Parquet

Никаких внешних API, скачивания весов или GPU — всё запускается локально на CPU.

## Воспроизводимость

- Фиксированный `random_state=42` при train/val split.
- Детерминированный порядок кандидатов при ничьих.
- Кэширование гарантирует идентичные результаты при повторных запусках.
- Полный цикл: `uv run python scripts/make_submission.py` -> `outputs/answer.csv`.
